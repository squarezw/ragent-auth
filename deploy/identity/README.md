# External production configuration

No deployment endpoint or environment identifier is embedded in this repository. Keep the real JSON outside all checkouts and image build contexts. Copy [config.example.json](config.example.json) to a protected external location, replace every example value and review the exact callback origins, trusted source networks and upstreams against the target infrastructure. Example domains are reserved and example networks use TEST-NET; they are not deployable defaults.

```sh
python -m pip install -r deploy/identity/requirements.txt
python deploy/identity/prepare.py --config-file "$DEPLOYMENT_CONFIG" --output-dir "$CANDIDATE_DIR"
python -m unittest discover -s deploy/identity -p 'test_*.py'
```

Both CLI arguments are required. The generator validates all configuration before writing, refuses existing output and output inside the repository, generates fresh independent RSA/cookie/bridge/client/database secrets, and writes files0600/directories0700. Every enablement flag remains false. It does not contact a server, read existing production keys or change a database. Output includes disabled app overlays, backend overlay, Compose env, least-privilege initial SQL, rendered Nginx configuration, a certificate deploy hook and a manifest. Do not print, commit or source generated contents. Initial provisioning is for a new installation only; upgrades retain existing secrets, clients and database roles.

Configuration keys explicitly describe HTTPS issuer/frontend/account bridge origins, CloudBase environment ID, database host/port/name/role, Docker network/gateway, trusted bridge CIDRs, external secret directory, certificate directory, ACME webroot, CA bundle, frontend Nginx snippet path, actual protocol/bridge HTTP upstreams, image and app list. App `kind` is `ragent` or `mt`; every client has a unique ID, origin and exact HTTPS `/api/auth/oidc/callback` URI. Wildcards, credentials, query strings and callback fragments are rejected. Frontend UI assets are proxied over verified HTTPS. The bridge allowlist ends in `deny all`; unrestricted source networks are rejected.

Templates under `nginx/` and the certificate hook are intentionally not directly installable: only the generated copies have their literal `{{PLACEHOLDER}}` tokens substituted. Rendering does not evaluate shell or Nginx variables, so `$request_uri`, `$uri` and forwarding variables remain intact. Install the generated frontend snippet at the configured path. Install the HTTP bootstrap vhost first; after obtaining a certificate for the configured issuer hostname, replace it with the generated HTTPS vhost, never install both. Install the bridge snippet inside the existing bridge HTTPS server while preserving unrelated routes. Run `nginx -t` before every reload. Install the rendered certificate hook root-owned/executable; it reloads only for the configured issuer hostname.

Provide the configured ACME webroot, issuer hostname and operational contact to the existing certificate client. Add the issuer hostname to the configured CloudBase environment's domain allowlist and verify enabled phone authentication without replacing existing entries. No administrative credentials belong in this project or container.

Provision the SQL only after backup/approval with an administrator, using a protected file and `ON_ERROR_STOP`; never use the runtime role for migration. Transfer generated secrets securely to the configured secret directory. For the UID1000 container, deliberately convert ownership/modes to root:1000 directories0750/files0440 (or owner1000/files0400); a workstation0700 tree is unreadable to that container. Merge backend/app overlays into existing protected settings, never overwrite unrelated environment values. Replace the backend Redis placeholder with the existing authenticated URL separately.

See [production packaging](../../PRODUCTION.md) for Compose/secret-loader details. Validate discovery, exact callbacks, verified TLS, machine bridge bearer plus source ACL, external bridge403, same-origin UI/CSRF, disabled and pending-tenant accounts, persistent session renewal and controlled phone authentication before enabling one client at a time. MT new-user enrollment remains false. No business roles are asserted by the issuer. Record commit/image digests and redacted evidence; never log tokens, cookies, signed callback query strings or generated SQL. Roll back app flags/image/vhost as needed while retaining all account data, stable mappings, secrets and backups.

Central sessions/grants last seven days and access/ID tokens ten minutes. Updating this policy requires rebuilding the independent identity image. Existing expired sessions require sign-in; local application logout is separate from global logout.
